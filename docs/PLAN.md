# Delivery plan and evidence gates

Milestones are sequential. Scope changes require updating [SPEC](SPEC.md), [ARCHITECTURE](ARCHITECTURE.md), [RESEARCH](RESEARCH.md), and [STATUS](STATUS.md) where affected. Passing a milestone's engineering tests does not establish a trading edge. Versions and thresholds are frozen before each evaluation period.

## Git milestone branches

`main` is the accepted-milestone branch; each active milestone develops and undergoes acceptance on its own branch (`v0`, then `v1`, `v2`, and so on). The existing `main` contained the unaccepted V0 implementation before this policy; that history was preserved. The accepted V0 source commit is `d26241151331795cf5005ba09d5f176d1efb6b22`, verified by the official run report and manifest without a dirty suffix. Future milestone acceptance soaks likewise use one exact clean commit; a code change requires a new qualifying run.

After all V0 gates pass, verify a clean and fully validated `v0`, merge it into `main` without rewriting history, create an annotated `v0-complete` tag on the resulting `main` commit, and push `main`, `v0`, and the tag. Only then branch `v1` from the updated `main` when V1 work begins. Develop V1 exclusively on `v1` until its acceptance gates pass; merge and tag it the same way. Repeat for later milestones. Never delete existing milestone branches, force-push, or rebase shared history.

## V0 — Data collection and deterministic replay

**Exact scope.** Implement one public, unauthenticated Kraken Spot WebSocket v2 `book` subscription for `BTC/USD` at depth 100, plus automatic heartbeat and one ordered public `AssetPairs?pair=XBTUSD` metadata GET before the socket. Coinbase Exchange Level 2 was replaced because its current authentication requirement contradicts the repository's no-account rule. Preserve raw frames/control events with receipt, admission and nondecreasing usable times; normalize to `BookSnapshot`, `BookDelta`, `Heartbeat`, `ProductMetadata`, `SourceStatus`, and `ClockTick`; maintain one checksummed Level 2 book and quality state; replay the verified committed tape through the identical normalizer/quality/book processor. The manifest is provenance, never a market-state side input. No signals, intents or trading functionality are in V0.

**Explicit non-scope.** No account keys, private channels/APIs, order management, trades, REST book bootstrap, L3, candles, multi-product joins, feature engineering, regime/signal/decision models, or paper P&L. The Coinbase public rejection tape is historical failure evidence, not an active source.

**Deliverables.** Go module; `cmd/collector`, `cmd/replay`, and `cmd/v0report`; single ingress/epoch coordinator; versioned raw segment writer/reader with CRC32C, SHA-256 prefix commit frames and recovery; canonical normalized/state JSONL; Kraken public metadata and WebSocket adapters; single-owner quality/book state with Kraken top-ten checksum validation; monotonic availability watchdog; applied/published progress journal and recovery report; bounded queues; metrics and structured logs; synthetic tapes and expected hashes; runbook. The run manifest records run ID, source endpoint, product/depth, start/end, code revision, Go version, config/schema and segment hashes, metadata ordinal, progress marks, and clean/unclean termination. A separate atomic run report starts before capture, refreshes every five seconds, and marks interrupted runs incomplete on the next startup. The 24-hour acceptance soak is mandatory before V0 completion.

**Clock, recording and replay rules.** One-second ticks enter the same ingress order as source observations. `ReceiveTime` is stamped after a complete frame read, `AdmissionTime` is the actual acceptance time, and `UsableFromTime` is no earlier than admission and nondecreasing. A read-completed frame admitted after a tick cannot affect that tick. Kraken snapshot/update `timestamp` is `EventTime`; heartbeat has no source timestamp. Never sort by event time. A wall/monotonic elapsed discrepancy over two seconds records `CLOCK_ANOMALY` and ends the run; a new run needs ten stable one-second observations and a fresh metadata/snapshot sequence. Replay uses only verified commits, recorded time/ticks, and ordinal order. Speed cannot change canonical hashes. Recovery reports valid, committed, applied, published, and uncertain prefixes separately.

**Quality and book rules.** Start `STARTING`; require ordered online pair metadata, exact `book:BTC/USD:depth=100:snapshot=true:req_id=1` acknowledgment, and a current-epoch checksummed snapshot. Kraken emits heartbeat only during otherwise quiet periods, so connection activity is refreshed by either a book message or automatic heartbeat. A book or heartbeat gap over three recorded seconds invalidates. Book inactivity over 30 seconds with continuing heartbeats is `DEGRADED`. The source supplies no contiguous book sequence; each snapshot/update checksum verifies the local top ten levels. Preserve raw decimal spellings for checksum, apply all absolute-size updates, truncate to 100 levels per side, then verify CRC32. Wrong symbol, duplicate ack, malformed message, missing/mismatched checksum, crossed/empty book, disconnect, or old epoch invalidates and requires a fresh snapshot. No stale previous generation is carried forward. A separate monotonic gate closes on live processing lag independent of replay health.

**Initial metrics.** Frames/bytes per type, unknown/invalid/wrong-symbol and checksum failures, ingress queue fill/blocked time, fsync latency, committed/applied/published marks, receipt-to-admission/commit/apply/publish lag, tick and gate-close lag, epoch/retry counts, book/heartbeat activity age, snapshot wait, book generation/levels/spread/crossed/empty incidents, clock anomalies, time unhealthy/degraded, and replay prefix/hash mismatches. Do not use unbounded raw IDs as metric labels.

**Exact acceptance tests.** Fixtures and commands must demonstrate:

1. **Identity/protocol:** metadata is ordered before socket open; outbound subscribe contains only the declared book symbol/depth/snapshot/request ID. Missing/extra/wrong/duplicate acknowledgment, wrong/missing book symbol, and snapshot before acknowledgment never reach `HEALTHY`. Unknown status/new message types stay raw and are ignored.
2. **Capture order/epoch:** a frame read before but admitted after a tick affects only later state. A close barrier commits before a new epoch; delayed old-epoch frames/status cannot invalidate its new book. Assert state after every ordinal.
3. **Raw commit/recovery:** verify framing bytes/length/CRC, ordinal continuity, prefix and segment hashes, manifest, normalized JSONL and decimals. Crash at write, data fsync, marker write/fsync, state apply and output write. A complete unmarked frame is excluded, a missing manifest flags/rebuilds provenance without erasing commits, and a bit flip fails closed. Report valid, committed, applied, published, and uncertain suffixes.
4. **Book golden:** verify source [checksum example](https://docs.kraken.com/exchange/guides/websockets/book-checksum-v2), raw trailing-zero precision, same-price repeated changes, zero deletion, absent-level zero, depth truncation, second snapshot, pre-snapshot/old-epoch update, duplicate canonical snapshot price, zero-size snapshot, over-scale decimal, wrong checksum, empty/crossed book. Invalid whole messages change no book bytes and never leave a generation healthy. Verify sorted book hash, BBO, generation and health at each ordinal.
5. **Time/availability:** out-of-order exchange times, equal receipt stamps, no heartbeat event time, overtaken frame/tick, late market frame, and poison future metadata. Verify nondecreasing usable time, actual admission preservation under a small wall correction, no prior output change and no manifest side-input. Inject a large clock jump and require a new stable run/metadata/snapshot.
6. **Health/backlog:** expire activity after over three recorded seconds; quiet book with live heartbeat becomes `DEGRADED` after 30 seconds. Freeze recorder or state over two live seconds while the socket remains open; gate closes within bound plus 250 ms. Handoff/commit over one second fails closed, without stale output or invisible drops.
7. **Lifecycle:** transport disconnect, acknowledgment/snapshot timeout, malformed frame, checksum mismatch, slow consumer, disk-full, SIGINT/SIGTERM. Verify bounded retries only for recoverable source faults, orderly close barrier, all high-water marks, and explicit next-run gap after an incomplete run.
8. **Determinism/parity:** fast, paced and stepped replay of the same committed tape produce identical normalized, quality and book hashes. Compare live/replay on the common acknowledged applied prefix, report other suffixes and operational gate intervals separately, and never rewrite measured live apply/publication times from replay speed.
9. **Information barrier:** one-event-at-a-time processor cannot query future records, final manifest, or a replay iterator. Poison later frames/metadata and verify earlier output and contributing ordinals do not change.
10. **Soak:** capture at least 24 continuous hours of the configured feed. Verify initial and five-second atomic run-report snapshots, preserved raw/derived/progress prefixes after forced interruption, next-start `INCOMPLETE` marking, and rejection of an interrupted report by the final audit. Report frame/byte/storage rates; p50/p99/max admission, commit, apply and tick lag; fsync latency; queue maxima; progress marks; time unhealthy/degraded; quiet-book intervals; clock adjustments/offset if measured; all reconnect/gap/checksum-invalid events; and exact live/replay common-prefix comparison. Pass with zero unreported loss or unexplained divergence. Disconnections must be marked and resnapshotted. Synthetic tapes cannot substitute for this test.

**Gate to V1.** All V0 tests, `go test ./...`, `go test -race ./...`, `go vet ./...`, the public live smoke, and the 24-hour capture/replay soak must pass or have explicit unresolved status. Archive manifest, comparison prefix and suffix/gate incident report. No prohibited connectivity exists. Do not start V1 before this gate.
## V1 — Deterministic baseline analytical engine

The initial V1 engineering definitions, deliberately frozen before inspecting outcomes, are in [V1_DESIGN](V1_DESIGN.md); its independent attack is in [V1_DESIGN_REVIEW](V1_DESIGN_REVIEW.md). The one-day accepted V0 tape is development evidence only. It cannot validate durable profitability or serve as a sealed final period. V1 acceptance requires the explicit gate in that design and an honest exploratory report; positive returns are not required. Keep all V1 work on `v1` and leave the merge/tag for separate human review.

**Scope.** Add the single shared `AnalysisEngine`, midpoint return/volatility/trend and spread/depth features, a simple documented regime summary, one or two baseline signal rules, a conservative quote-aware hypothetical cost model at a predeclared reference notional, and `LONG`/`SHORT`/`NO_TRADE` intents. Use only V0 feeds and explicit fixed-horizon labels. A bearish forecast yields `NO_TRADE` unless a hypothetical short mechanism and borrow/carry costs are specified. Add a run manifest for feature versions, assumptions, and intent provenance. Emit probabilities only after chronological out-of-fold, purged, predeclared calibration validation; otherwise omit those fields.

**Non-scope.** No trade-flow, derivatives, cross-market signals, ML, execution, leverage/size, or optimized parameter sweeps. No claim of economic value from software correctness.

**Deliverables and tests.** Pure incremental feature/state packages; baseline and cost definitions; intent schema/journal with measured live decision-ready/publication times; fixture tests for warm-up, missing/stale book, quote generation and maximum age, as-of bar revisions, late events, `NO_TRADE` reasons, cost-margin gate, and common-prefix output parity. Before any return result, freeze a reference notional, earliest-entry latency rule, first eligible healthy **ask for buy/bid for sell** and opposite-side exit rule, depth consumption/slippage, round-trip fees, horizon measured from feasible entry, borrow/carry where relevant, and absent-endpoint censoring; no favorable earlier quote may be selected. A recorder/output stall across a price jump and a hand-calculated moving-BBO/thin-depth/missing-exit tape must prove the evaluator cannot backdate entry. Report midpoint prediction skill separately from net hypothetical opportunity. Chronological evaluation includes `NO_TRADE`, random direction at matched action frequency, always-long where meaningful, simple momentum and reversion under identical costs. Freeze a health eligibility mask and report calendar coverage, reason counts, and outage-driven versus model-driven abstention. Report excluded-period moves/volatility only if independently observed; otherwise mark unknown. Compare baselines on paired eligible timestamps; an outage clustered around adverse moves must appear as lost coverage, not improved model skill. Test leakage with poisoned future values and shuffled event-time order.

**Acceptance/evidence gate.** Engineering invariants pass; the experiment ledger and evaluation protocol are frozen and report uncertainty, trade frequency, coverage, regime breakdown and costs. V1/V2 comparisons use reusable chronological **development** walk-forward folds, not the sealed final period. Proceed to V2 only if baseline behavior and limitations are understood and enough clean data exist; positive returns are not mandatory and cannot be manufactured by retuning an exposed final period.

**V1 gate result (2026-09-30).** The engineering gate passed on `v1` with two byte-identical full-tape replays, accepted V0 hash recovery, a warmed public live smoke with exact V1 intent parity, and an adversarial [final audit](V1_FINAL_AUDIT.md). The policy made zero actions under frozen conservative costs; this is a documented baseline limit, not a profitability result. The separate human review subsequently merged/tagged V1 before creating `v2`; the V1 closeout itself did not create `v2`, merge `v1`, or tag completion.

## V2 — Multi-signal engine

**Branch and frozen core design (2026-09-30).** `main` contains the accepted V1 merge and annotated tag; V2 was developed and accepted on `v2`, pending separate human merge/tag. [V2_DESIGN](V2_DESIGN.md), its [adversarial review](V2_DESIGN_REVIEW.md), and [experiment ledger](V2_EXPERIMENT_LEDGER.md) predeclared the core single-feed families, evidence votes, costs, research population and acceptance gate. Public trades, derivatives and cross-market feeds remain postponed until a separate global admission/join design and matching historical tape exist.

**Implemented scope.** The accepted Kraken BTC/USD tape alone drives frozen V1 price features and three V2 family results: 60-second trend persistence, 300-second displacement reversion, and 30-second top-five displayed book-depth pressure. Trend/reversion share one price-mechanism vote; pressure is one independent *input mechanism*, not a proven independent predictor. Family health/status, disagreement, fixed aggregation, explicit opportunity cost screen, separate V2 intent/journal and downstream 300/30-second paired research are implemented. The default spot policy has no short feasibility mechanism. No second feed or optional join was admitted.

**Non-scope.** No large indicator catalogue, complex ML, account/execution features, unverified alternative data, or V3 calibration. Later feed work requires a new source card, global admission order, historical replay tape and fresh preregistered incremental hypothesis; its absence does not invalidate this completed V2 core.

**Acceptance/evidence gate.** Preserve V0/V1 bytes and benchmark; pass anti-future/health/cost/race tests, two byte-identical complete accepted-tape replays with exact V0/V1 hashes and all paired/censored episodes accounted for, honest family/cohort/control and cost report at each declared horizon, a warmed public read-only live smoke with exact raw-replay V2 intent parity, and a final adversarial audit. A negative or zero-action economic result is permitted. Do not claim independent family alpha or profitability from the exposed one-day tape.

All Go/race/vet/format/diff checks passed; [V2_RESEARCH_REPORT](V2_RESEARCH_REPORT.md) reports the zero-action policy and negative assumed-cost hypothetical scenarios, and [V2_FINAL_AUDIT](V2_FINAL_AUDIT.md) closes the adversarial gate. ## V3 — Statistical / ML modelling

**Active branch and scope (2026-10-02).** V2 was merged/tagged on `main` at `39f9ee7`; V3 work is on `v3`. The [data assessment](V3_DATA_ASSESSMENT.md) finds the exposed one-day tape insufficient for calibration or final statistical acceptance. Proceed with the predeclared small regularized logistic/base-rate engineering comparison in [V3_DESIGN](V3_DESIGN.md), deterministic row export, purged/embargoed folds, artifact verification and shared read-only inference. Ridge is exploratory if supported; boosted trees are postponed for insufficient effective sample. The accepted V0/V1/V2 engines and availability barrier remain benchmarks.

**Non-scope.** No deep models by default, online learning without a frozen evaluation protocol, training on final test, or using final test for model selection.

**Deliverables and tests.** Reproducible training pipeline, model artifact/hash, time-split and walk-forward reports, calibration/reliability counts, sensitivity and parameter-stability checks, complete [experiment ledger](V3_EXPERIMENT_LEDGER.md), leakage probes and ablations. Generate calibrator inputs from chronological out-of-fold predictions with purge/embargo for overlapping outcome horizons; fit any learned regime thresholds and family selection inside each fold. The accepted V1 regime thresholds are fixed and need no fitting. Predeclare effective independent episode count, bucket uncertainty, and an acceptance metric before populating probability fields. Synthetic correlated-family, future-fitted-regime and calibration-leakage fixtures must reject in-sample evidence. Compare to all earlier baselines after identical costs. The [future sealed-test protocol](V3_SEALED_TEST_PROTOCOL.md) freezes duration, minimum counts and statistical/economic gates before outcomes exist.

**Acceptance/evidence gate.** Engineering completion requires reproducible dataset/model/inference artifacts, correct chronological folds and causal live/replay parity, full validation commands and final adversarial audit even if all decisions remain `NO_TRADE`. Development walk-forward results are disclosed but cannot satisfy statistical acceptance. The final gate requires a frozen candidate and later unopened chronology meeting the exact [sealed protocol](V3_SEALED_TEST_PROTOCOL.md); open it once. If its result prompts redesign, that period becomes development evidence and new future data are required. Do not merge/tag V3 or begin V4 in the V3 closeout.

## V4 — Forward paper validation

**Scope.** Run the frozen analysis engine prospectively on recorded public feeds and publish intents to an append-only research journal. Evaluate subsequent market outcomes with predeclared label and hypothetical friction rules. Track availability, latency, drift, calibration and abstention.

**Non-scope.** No real orders, positions, account APIs, wallets, leverage selection, or unattended execution. Paper observations are not fills.

**Deliverables and tests.** Signed/frozen run manifest, continuous raw capture, immutable intents, outcome evaluator that cannot edit earlier intents, monitoring and incident log. Replay reproduces canonical intent decisions through the common acknowledged applied prefix; original measured publication timestamps and operational gate intervals come from the live journal, not replay speed. Unpublished or unapplied suffixes are reported separately; outages yield reasoned `NO_TRADE` or unavailable output. Forward metrics include sample sizes, coverage, costs, regime breakdown and uncertainty.

**Acceptance/evidence gate.** Sufficient predeclared forward duration and sample count (set before V4 begins), no unexplained live/replay divergence or unmarked data gaps, and transparent comparison to V1/V2/V3 baselines. This milestone ends at research evidence; any execution system would require a separate project and authorization.
