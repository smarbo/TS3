# Functional and research specification

Status: V0, V1 and V2 engineering milestones are accepted and merged/tagged on `main`; V3 development is active only on `v3`. V2's frozen single-feed contract is in [V2_DESIGN](V2_DESIGN.md) and its acceptance evidence in [V2_FINAL_AUDIT](V2_FINAL_AUDIT.md). V3's data sufficiency and statistical contract are in [V3_DATA_ASSESSMENT](V3_DATA_ASSESSMENT.md) and [V3_DESIGN](V3_DESIGN.md). No validated predictive or economic strategy result exists.

## Purpose and boundary

Build a continuously running Go research engine that turns public market events into `LONG`, `SHORT`, or `NO_TRADE` analytical intents. The eventual path is ingest → quality → normalization/synchronization → market state → features → regime → signal models → calibration → evidence aggregation → opportunity/cost/risk filter → intent. Each stage must expose its health and provenance. `NO_TRADE` is a normal, first-class decision, including when expected opportunity is inadequate or evidence is unavailable.

The repository must never contain exchange account authentication, private APIs, wallet/deposit/withdrawal code, order submission, live execution, or management of actual positions. Intent is an informational output, not an instruction to an exchange. Account sizing, leverage, and execution belong downstream. A later *hypothetical* feasibility study may model minimum notional, precision, and account constraints without creating account connectivity.

## Governing invariants

1. **One analytical path.** `LiveSource` and `ReplaySource` produce the same committed raw event envelope into the same normalizer and, from V1, the same `AnalysisEngine`. There are no parallel live/backtest implementations of features, regimes, signals, costs, or decisions. Source-specific code ends at input adaptation. Replay must reproduce canonical state on the **common acknowledged applied prefix**; a committed but unapplied crash suffix is reported separately, not claimed as live parity. Operational wall-clock and publication diagnostics are separately journaled and are not recomputed from replay speed.
2. **Availability, not event-time clairvoyance.** State evaluated at logical time T may depend only on records whose `UsableFromTime <= T` and that have already entered the serialized stream. `ReceiveTime` is observation at the socket, while `AdmissionTime` is the serialized ingress point; V0 `UsableFromTime` is no earlier than `AdmissionTime`. Exchange `EventTime` may be earlier than either and never grants earlier access. A snapshot with no exchange timestamp has unknown `EventTime`, not a fabricated one. Publication time is separate when a source supplies it. Replay must never hand a future-complete dataset, final run manifest as a market side input, or unrestricted historical query to analytical components.
3. **Deterministic order.** Preserve recorder ordinal, including control events and clock ticks. A tie in timestamps is resolved by ordinal. Calculations use specified numeric/rounding rules, stable iteration order, frozen configuration, and versioned schemas. Any nondeterministic model or parallel computation must have a reproducibility contract before use.
4. **Health is input.** A required feed that is disconnected, stale, invalid, or in a gap makes dependent signals unavailable. Unknown is distinct from zero. No stale last-known quote is silently treated as current. Severe uncertainty defaults to `NO_TRADE` with reason codes.

## Accepted V2 analytical contract

The single public Kraken BTC/USD book and recorded ticks remain sufficient. V2 preserves the V1 feature snapshot and adds three versioned results: 60-second return persistence (`trend.v2.1`), 300-second midpoint displacement reversion (`reversion.v2.1`), and persistent top-five displayed-depth imbalance (`book_pressure.v2.1`). Trend and reversion share one price-mechanism vote; book pressure supplies one separate 30-second confirmation vote and is evaluated at that horizon. Each family reports `ACTIVE`, `NEUTRAL`, `UNAVAILABLE`, or `INVALID` with a reason, horizon and ordinal/generation provenance. Both mechanism votes must actively agree for a candidate direction; conflict and missing diversity are explicit abstention reasons. `WIDE` quote regime suppresses all three families. The opportunity screen uses the V1 USD 100 side-correct displayed-depth cost, 20-bp taker fee and 5-bp allowance per side, plus a fixed 10-bp margin. Its observed past-move magnitude is a screening proxy, not calibrated expected return. Default spot configuration cannot issue `SHORT` without a documented short mechanism. No trades, optional second feed, private account function, probability model or execution path was added. See the [research report](V2_RESEARCH_REPORT.md) for the zero-action development result and its limits.

## Time and information rules

All persisted instants are UTC RFC3339 with nanosecond-capable representation; timestamps are parsed as instants, never local civil time. `ReceiveTime` is captured immediately after a complete source frame is read, before decoding. `AdmissionTime` is stamped when the serialized ingress accepts a frame or control observation. `UsableFromTime` is the nondecreasing logical admission time, never earlier than that record's `AdmissionTime`; a pre-admission observation is not retrospectively inserted ahead of a tick. `ProcessingTime`, decision-ready time, publication time, and hypothetical-entry time are different operational or evaluation concepts and must not be substituted for receipt or exchange time. Exchange `EventTime` is optional. Source `PublicationTime` is optional and only set when semantically documented. A record is processed in recorder order; equal logical times remain ordered by ordinal. Control ticks are recorded in the same order and drive deterministic analytical staleness transitions. A separate monotonic live availability gate suppresses stale output if processing stalls. The engine must not query the OS clock directly.

A large UTC wall-clock jump ends the current run; it does not get clamped into a long-lived false future. A new run begins only after a stable wall/monotonic interval and a fresh book snapshot. In V0, no analytical output is published while clock health is uncertain. Replay consumes the recorded run break and never repairs its timeline from the replay host's clock.

Late data is admitted only on arrival and retains its historical event timestamp. A window may use late data prospectively, but past features/decisions are immutable; no retroactive insertion or backdated trading signal. If a feed's timestamp is implausibly in the future relative to receipt, flag it and make affected event-time features unavailable pending investigation. Cross-feed synchronization uses each feed's `UsableFromTime`, declared freshness, and explicit cutoffs; interpolation from a later value is prohibited.

## Analytical philosophy and decision semantics

- Begin with mechanism-based, minimal features and robust baselines. Keep microstructure, short-term, intraday, and broader-regime horizons explicit. A short-lived quote fluctuation cannot override higher-horizon evidence without a tested rule.
- Regime is a multidimensional estimate (trend/range, volatility, liquidity, directional/mean-reverting, risk-on/off, abnormal/normal) with an `unknown` state for unsupported dimensions. Simple statistics precede hidden-state or complex ML methods.
- Each signal declares required feeds, maximum staleness, horizon, expected mechanism, and unavailability rules. Independent signal families must not be counted as independent evidence merely because they have different names; correlated features and shared labels require joint calibration.
- Separate directional prediction from opportunity. Expose direction score or a calibrated probability only when calibration evidence exists; expose expected gross/net return, uncertainty, horizon, supporting evidence, and health when supported. Never emit an unexplained generic confidence percentage.
- Before any probability field is emitted at any milestone, use chronological out-of-fold predictions, purge/embargo overlapping outcome horizons, fit regime thresholds and family selection inside training folds, and predeclare effective-sample and calibration acceptance rules. Otherwise omit the probability.
- Estimate `E[R_net | X_t] = E[R_gross | X_t] - E[cost | X_t]`. Cost assumptions cover fees, spread, slippage, funding where relevant, and instrument constraints. Require a predeclared margin above estimated uncertainty and cost. If inputs or calibration are insufficient, `NO_TRADE` is valid and should dominate.
- A `LONG` or `SHORT` intent expresses an analytical view with expiry and risk context. It is not an order, target position, size, leverage, or fill claim. A bearish forecast on spot data does not by itself establish a feasible short; without a stated hypothetical short mechanism and its costs, emit `NO_TRADE`. `NO_TRADE` includes reason codes (for example `DATA_UNHEALTHY`, `INSUFFICIENT_EDGE`, `DISAGREEMENT`, `UNCALIBRATED`, `SHORT_FEASIBILITY_UNKNOWN`).
- Every prospective cost estimate and directional intent must identify the quote generation and a predeclared maximum quote age. A current heartbeat is insufficient. Missing, unhealthy, or over-age entry-side quotes force `NO_TRADE`; an absent freshness policy is not permission to trade.
- Historical evaluation distinguishes a signal's market `as_of_time`, actual live decision-ready/publication times, and the earliest hypothetical entry after predeclared latency. It may use only a healthy quote first available at or after that entry boundary. Midpoint direction skill is reported separately from executable-side, round-trip net opportunity. Excessive live processing lag makes directional output unavailable.

## Reproducibility and validation

Persist raw source frames, normalized schema/version, source identifiers, ordered control events, dataset/segment hashes, code revision, Go/toolchain version, configuration hash, feature/model/calibration versions, and all assumptions for each run. Derived data are regenerable from immutable raw input. Distinguish source observations from engineered labels. Record product universe and delisting/status history to avoid survivorship bias. Never replace a historical observation with a later corrected value without recording its publication and receipt times.

For the V0 live soak, persist operational run metadata before capture and refresh an atomic, fsynced progress report during capture. Preserve verified raw commits and derived progress through interruption; mark any run left active by an unexpected stop as incomplete on the next startup. An interrupted run cannot satisfy the 24-hour acceptance gate. Operational reports are never analytical market inputs.

Research uses chronological development train/validation folds and a sealed final test period. Register hypotheses, thresholds, cost assumptions, selection criteria, and attempted variants before evaluation. Development walk-forward folds may be reused with full search disclosure; the final period is opened once for a frozen candidate. A redesign informed by that result needs new, later untouched data for a fresh final test. Fit scalers, calibration, regime thresholds, feature selection, and eligibility policies only within training/development folds, with purge/embargo for overlapping labels. Apply realistic spread, fees, slippage, latency and, where applicable, funding/borrow. Test across regimes, gaps, and product status changes. Freeze and report a health-based eligibility mask, calendar coverage, exclusions, and outage-driven versus model-driven abstention; compare baselines on paired eligible timestamps. Report excluded-period market moves/volatility only where independently observable; otherwise mark them unknown rather than infer them from missing feed data. Inspect parameter stability, ablations, sensitivity, probability calibration with effective-sample/bucket uncertainty, bootstrap or Monte Carlo where dependence structure permits, and multiple-hypothesis/data-mining effects. Explicitly audit look-ahead, leakage, survivorship, and unrealistic fill assumptions. Compare against `NO_TRADE`, random direction with the same opportunity frequency, always-long where meaningful, simple momentum, and simple mean reversion. Favor simpler methods unless out-of-sample evidence justifies complexity. No result is a claim of profitability without the full evaluation protocol and uncertainty.

## Definition of done

For the design pass: the five requested documents and this file are internally consistent, identify an implementable V0 contract and acceptance tests, cite current primary-source API facts, and contain no production trading functionality. For later software milestones: all specified acceptance tests pass; deterministic replay and no-future-information tests pass; quality and failure paths are observable; source provenance and reproducibility manifest are complete; no prohibited connectivity exists; milestone evidence is recorded in `docs/STATUS.md`. Passing software tests alone never establishes predictive value.
